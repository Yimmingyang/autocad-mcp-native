# AutoCAD MCP 连接器使用说明

适用版本：AutoCAD MCP Native Bridge v0.6.2（Windows x64）
下载： [GitHub Releases 最新版](https://github.com/Yimmingyang/autocad-mcp-native/releases/latest)

## 1. 连接器到底连接谁

连接器负责把三个部分接起来：

1. **AutoCAD 插件**：在 CAD 进程内运行，提供读写当前图纸的 AutoCAD API 能力。
2. **本机 MCP 服务**：Node.js 服务通过 Windows 命名管道联系 CAD 插件，并用 MCP stdio 向 AI 客户端提供工具。
3. **AI 客户端**：当前安装器能检测和写入配置的是 OpenAI Codex 与 DeepSeek Harness。

因此，界面里的“CAD 已连接”表示 MCP 服务已通过本机管道收到 CAD 插件响应；“MCP 工具可用”表示服务启动并返回了工具清单；“客户端配置已写入/检测到”只表示配置文件存在或已更新。**最后一项不等于 AI 客户端当前会话已经加载配置。**

本机连接路径为 `AutoCAD 插件 ⇄ Windows 命名管道 ⇄ MCP stdio 服务 ⇄ AI 客户端`。CAD 和使用该配置的 AI 客户端应在同一台 Windows 电脑上运行。本版本不使用 TCP 端口或 OAuth，也不能据此显示任意电脑、任意 AI 程序的实时连接状态。除 Codex、DeepSeek Harness 外，其他 MCP 客户端需要自行配置，连接器不会自动发现或管理它们。

## 2. 下载与安装

1. 在 [Releases 页面](https://github.com/yanmiong/autocad-mcp-native/releases/latest) 下载 `AutoCadMcpInstaller.exe`。
2. **先关闭所有 AutoCAD 窗口**，避免 CAD 正在占用插件文件。
3. 运行安装器，在 CAD 列表选择要使用的 AutoCAD 年份；确认选中的是实际要启动的那套 CAD。
4. 在 MCP 客户端列表选择 Codex 或 DeepSeek Harness。列表只会显示安装器识别到的客户端。
5. 点击“安装/修复”，等待编译、部署与配置写入结束；安装过程需要网络访问 GitHub、NuGet、Node.js 官方分发源及必要的 Microsoft SDK 下载源。
6. 安装完成后启动所选 AutoCAD。首次加载时若出现插件加载提示，确认加载 `AutoCadMcp.bundle`；若被安全加载设置拦截，先检查安装器是否已将该 bundle 加入 CAD 的可信路径，不要通过全局关闭安全加载来规避。
7. 启动/重启 AI 客户端，并创建一个新会话，使其重新读取 MCP 配置。

安装器会备份已有插件和客户端配置。插件默认安装位置：

```text
%APPDATA%\Autodesk\ApplicationPlugins\AutoCadMcp.bundle
```

配置位置：

| 客户端 | 配置文件 |
|---|---|
| OpenAI Codex | `%USERPROFILE%\.codex\config.toml` |
| DeepSeek Harness | `%DSH_HOME%\cordis.patch.yml`；若未设置 `DSH_HOME`，则为 `%USERPROFILE%\.dsh\cordis.patch.yml` |

Harness 配置使用官方 `@deepseek-ai/dsh-mcp-client` stdio 客户端。安装器管理的配置片段可以更新；首次改写前会保存带时间戳的备份。

## 3. 检查连接状态

AutoCAD 和所选客户端均启动后，在连接器中点击“测试 MCP 连接”。按界面显示分别判断：

| 检查项 | 通过表示 | 不表示 |
|---|---|---|
| AutoCAD/桥接状态 | 本机 MCP 服务的 `get_bridge_status` 已收到 CAD 插件响应 | 不代表图纸几何已正确，也不代表 AI 已加载工具 |
| MCP 服务/工具发现 | 本机 MCP 子进程启动、完成握手，并由 `tools/list` 返回工具清单（当前版本测试发现 24 项入口） | 不代表 AI 客户端本轮会话已重新读取配置 |
| 客户端配置 | 被选客户端的配置路径/托管配置已找到或写入 | 不代表客户端进程在线或真实调用成功 |

然后在 AI 客户端中确认工具列表出现类似 `mcp__autocad-native__...` 的 AutoCAD 工具。先调用 `get_bridge_status` 或 `drawing_summary` 做只读检查；只有 AI 会话内实际出现工具并成功调用，才能确认该会话已接通。若安装器三项通过而 AI 里没有工具，完全退出并重开客户端，再新建会话重试。

## 4. 用 AI 读取和编辑图纸

### 只读检查

先打开目标图纸并确认它是当前活动文档，然后要求 AI：

> 使用 AutoCAD MCP，只读取当前活动图纸。先调用 `get_bridge_status` 和 `drawing_summary`，报告文件、单位、图层、实体概况与范围；不要修改图纸。

工具可读取图纸状态、单位、范围、图层、模型空间实体、尺寸、文字及实体属性，并可按类型、图层和条件筛选。实际可用名称和参数以客户端当前工具列表及 [`API.md`](API.md) 为准。

为避免 AI 用自己的提取结果证明自己“读全、读对”，新增 `audit_drawing_read` 作为确定性模型空间清点：逐个遍历模型空间对象，返回对象数、实体数、DXF 类型统计、无法打开对象样例和未分类类型。该结果由插件代码生成，不由 AI 自行估算；但它只证明数据库清点/对象分类覆盖情况，不证明设计意图、尺寸正确性或视觉可读性。核对结果必须保留标注值、实体测量值和疑点的来源，不能把同一次提取的重复复述称为独立验证。该功能已在 AutoCAD 2025 / R25.0.0.0 实机读取 8 个临时测试副本（仅执行读取调用）；每份的模型空间实体计数与几何读取计数一致，0 几何读取错误、0 未分类类型。该结果验证的是这些测试文件的覆盖情况，不验证设计意图。

### 原生读取与 OCR 的配合

普通矢量 DWG 中的 `TEXT`、`MTEXT`、尺寸、圆弧和线段本来就是数据库对象；应优先用 MCP 读取其文字、标注测量值和几何坐标，不必再对同一内容重复 OCR。读取 `MTEXT` 时同时提供去格式的可读文字和原始格式内容，便于核对。`audit_drawing_read` 会把栅格图像/底图和代理对象单独标记：若图纸只有矢量对象，OCR 通常没有额外数据可补；若包含扫描图、`IMAGE`、OLE/PDF 等底图，则需要 OCR/视觉核对。当前连接器能提示这些对象，但**尚未内置栅格图区域的 OCR 引擎与坐标对齐流程**，不会把“发现底图”冒充为“已 OCR”。

### 编辑操作

编辑前先另存一份 DWG 副本。对清晰、局部的修改，可要求 AI 先读取目标实体、说明计划，再执行对应编辑。创建线、圆、多段线、弧、椭圆、文字、尺寸、填充、图层或块，以及复制、移动、旋转、镜像、偏移、阵列、删除和属性修改，均由 CAD 插件在活动图纸中执行。

复杂或批量修改优先要求：

1. 读取图纸并列出拟修改实体和依据；
2. 调用 `preview_drawing_plan` 预览计划，复核坐标、尺寸、图层和影响范围；
3. 确认计划后再调用 `apply_drawing_plan` 应用；
4. 完成后重新读取图纸，核对实体数量、关键尺寸和修改结果，并在 AutoCAD 中检查视图。

不要只凭“执行成功”判定工程图正确。尺寸依据、视图对应或工艺参数不明确时，先把待确认项列出，不要猜值。若调用超时或客户端断线，先重新读取图纸状态，确认上次操作是否已经生效，再决定是否重试，以免重复创建或移动。

## 5. 常见问题

### 安装器找不到 AutoCAD

- 确认 CAD 已安装并至少运行过一次，且不是仅有查看器。
- 重新打开安装器扫描；检查 CAD 安装目录中是否存在 `acad.exe` 和托管 API 文件。
- 对安装器尚未识别的发行版，不要选一个相近年份的预编译插件替代；本安装器会针对选定安装的 API 编译。

### 测试时 CAD 桥接没有响应

- 确认所选年份与当前打开的 AutoCAD 一致，并检查 CAD 是否仍在启动、弹窗等待或命令执行中。
- 确认 `AutoCadMcp.bundle` 已安装，CAD 启动时插件已加载；重新启动 CAD 后再测试。
- 若安全加载提示拦截，检查可信路径是否含本插件 bundle，不要修改全局安全级别作为首选处理。

### MCP 工具列表测试失败

- 检查安装目录中的 Node 运行时和 MCP 服务文件是否存在：

  ```text
  %LOCALAPPDATA%\AutoCadMcp\runtime\node\node.exe
  %LOCALAPPDATA%\AutoCadMcp\server\src\index.js
  ```

- 使用连接器执行“安装/修复”，让它重新部署服务；完成后再次测试。
- 如需收集诊断信息，记录连接器错误文本、所选 CAD 年份、客户端及安装器版本。不要在公开 issue 中附上含客户信息的 DWG、个人路径或凭据。

### Codex / Harness 里没有 AutoCAD 工具

- 安装器检测/写入配置后，完全退出客户端再打开，并新建会话。
- 检查对应配置文件中是否有 `autocad-native` 服务条目；Harness 还需确认客户端使用的 `DSH_HOME` 与连接器写入的配置路径一致。
- 如果连接器测试服务成功但客户端仍无工具，查看客户端 MCP 启动日志中的命令路径、stdio 错误与配置解析错误。连接器测试并不会代替客户端自身的加载测试。

### CAD 显示已连接，但编辑报错或图形结果不对

连接只验证桥接可达，不验证每个操作的输入、CAD 命令上下文或几何正确性。检查活动文档、目标实体是否仍存在、坐标与单位是否一致、图层是否锁定、对象是否为支持的类型。重新读取错误附近的图纸状态并缩小操作范围；批量修改先用 `preview_drawing_plan`，必要时从备份副本恢复。

### 更换电脑或升级 AutoCAD

在新电脑重新下载并运行安装器，重新扫描本机 CAD 与 AI 客户端，再执行安装/修复；不要复制旧电脑的插件 DLL 当作新电脑的安装包。安装器支持扫描 AutoCAD 2020–2027，但当前实机连接验证覆盖 AutoCAD 2025 / R25.0；其他版本需在对应 CAD 主机中完成加载与 `get_bridge_status` 测试后，才算该版本实机确认。

## 6. 更新、备份与移除

- 更新时下载 Releases 最新安装器，关闭 AutoCAD 后重新运行并点击“安装/修复”。
- 需要回退配置时，恢复安装器生成的客户端配置备份；插件目录也有原有文件备份。恢复前先关闭相关客户端与 AutoCAD。
- 移除时先关闭 CAD 和 AI 客户端，再从安装器/系统中移除插件 bundle，并删除客户端配置中由本项目写入的 `autocad-native` 条目；保留并核查其他 MCP 服务配置。不要直接覆盖整个客户端配置文件。

## 7. 兼容性与边界

- 平台：Windows x64。
- 安装器检测范围：AutoCAD 2020–2027；按目标安装的 API/运行时构建。
- 本机实际宿主验证：AutoCAD 2025 / R25.0。
- 安装器客户端配置：OpenAI Codex、DeepSeek Harness。
- MCP 通信：本机 stdio + AutoCAD 专用 Windows 命名管道，不监听 TCP。
- 检测到客户端、配置写入成功、MCP 工具列表可取、CAD 桥接握手成功、AI 会话真实调用成功是五个不同状态，应分别验证。

更多工具参数见 [`API.md`](API.md)，安装器细节见 [`安装器使用.md`](安装器使用.md)，故障排查见 [`故障排查.md`](故障排查.md)。
